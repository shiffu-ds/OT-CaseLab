# Feasibility and scoped backlog

Decision date: 1 October 2026. Local engineering is feasible with scripted mode, SQLite and CPU inference. Educational validation and public deployment require resources not currently established.

| Dependency | Available now | Gate / action |
|---|---|---|
| Content | Five original fictional drafts, translated facts, original rubrics, two CC0 schematics | Educator checks factual fidelity, language, objectives, scoring anchors and assets before reviewed publication |
| Educators | No confirmed reviewer or institutional agreement | Arrange course mapping and double-rating access; no endorsement inferred |
| Labelled data | No real learner trajectories or independent expert labels | Obtain relevant review, voluntary consent, annotation/adjudication and frozen learner/case splits |
| Hardware | Ordinary browser; local CPU path | Benchmark loaded models, memory and concurrency; no GPU/camera required for demo |
| Model weights | Optional downloads and provider SDK adapters | Check licences/revisions, offline/cache behavior; executing inference is distinct from validated quality |
| GenAI credentials | Optional; scripted provider requires none | Configure a genuine server-side key for live provider testing; cap use and disclose provider data handling |
| Hosting | Container configuration can be prepared locally | Authorized VM/domain/DNS/secrets, staging and public HTTPS verification still required |
| Budget | No hosting/provider spend authorized here | Measure tokens/time/bytes; choose provider using current account quotes; no promised free tier |
| Research | Protocol can be prepared | Relevant institution must determine review process before recruitment; no study has occurred |

Do not train an educational prediction model from generated labels and describe it as validated. Synthetic fixtures demonstrate pipeline mechanics. The default recommendation is an explicit weak-domain rule. Schematics can test the display and model invocation, but a natural-image detector may return no useful objects; representative staged photographic evaluation data remains missing.

## Ordered release backlog

1. R1: complete one-case journey with auth, persistence, learner image observations, original provisional rubric feedback, report and educator amendments.
2. Extend the same journey to all five drafts with honest review/demo labels and language display.
3. Integrate actual pretrained NLP/CV inference, approved evidence retrieval, bounded action selection, real MCP and durable jobs. Keep visible errors and original baseline behavior.
4. Build and test production containers; rehearse backup/restore in a disposable environment and prepare staging deployment.
5. Obtain educator reviews and permitted evidence; establish multilingual equivalence benchmark and source licensing.
6. Collect permitted longitudinal expert labels; compare grouped ML candidates against simple baselines and validate probabilities if displayed.
7. Conduct the approved pilot on unseen cases; report uncertainty, limitations and component ablations.

A working demo may be useful portfolio evidence even when measured learning benefit, trained recommendation quality and live hosting remain incomplete. Release gates are in [RELEASE_PLAN.md](RELEASE_PLAN.md), current checks in [IMPLEMENTATION_STATE.md](IMPLEMENTATION_STATE.md).
