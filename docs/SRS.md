# Software requirements and traceability

SRS v0.1 — 1 October 2026. The authoritative execution record is [IMPLEMENTATION_STATE.md](IMPLEMENTATION_STATE.md). A listed test scenario is an acceptance requirement, not a claim that it passed. Live contracts are generated by FastAPI at `/openapi.json` and `/docs` in local development.

## Main journeys

Student: sign in → select an available draft/published case → choose language → interview → describe the supplied image independently → save profile/goals/rationale → submit a frozen plan → inspect provisional scores, exact excerpts, available citations and uncertainty → see educator amendments/recommendation → export own report or delete eligible personal data.

Educator: sign in → inspect/create case drafts → create a new version → explicitly review/publish content → inspect authorized cohort attempts → add attributed score amendments and reasons. An old attempt remains attached to its original case and rubric. Publication does not constitute validation of a model or intervention.

Administrator: create educator/cohort users through the server CLI; manage operational configuration and authorized deployment. A complete institutional invitation/cohort-management interface remains backlog.

## Functional requirements

| ID | Requirement / acceptance behavior | Implementation trace | Verification scenario |
|---|---|---|---|
| AUTH-01 | Password credentials are hashed; opaque session cookie is HttpOnly, expiry/revocation enforced | `services/api/security.py`, models, auth endpoints | Login/logout/expiry and no plaintext database password |
| AUTH-02 | Unsafe authenticated requests need CSRF token; browser origin enforced | security and API middleware; web API wrapper | Missing/wrong CSRF, foreign Origin and login without Origin rejected |
| AUTH-03 | Students cannot become educators by supplying role; scope derives from live membership | schemas, policies, MCP auth/bridge | Extra-field role injection and forged identity rejected |
| CASE-01 | Five original adult rehab drafts with case versions, multilingual facts, objectives and rubrics | `data/demo/cases.json`, content service | Validate all case languages, IDs, facts, original rubric dimensions |
| CASE-02 | Demo eligibility, review and published state remain distinct | CaseVersion, educator publication endpoints | Draft shown only with explicit demo allowance; reviewed publication attributed |
| CASE-03 | Learner responses omit hidden facts, rubric anchors and draft evidence | public serializers | No hidden payload keys in case/attempt APIs or frontend bundle |
| CASE-04 | Published versions and bound attempts remain immutable | content/version service | New version differs; existing attempt still uses old version |
| LANG-01 | `en`, `ur`, `roman` accepted; Urdu paragraphs use RTL while code/numbers remain readable | schema and web language UI | Three language journey; keyboard interaction and RTL screenshot |
| LANG-02 | Equivalent OT reasoning receives equivalent feedback | benchmark protocol | Independent reviewed multilingual benchmark pending; UI translations alone insufficient |
| INT-01 | Interview remains case-consistent; unknown facts explicitly unknown | `ai/baseline.py`, providers, message endpoints | Known/unknown, contradictory, answer-key and out-of-scope questions |
| INT-02 | Scripted/provider mode and errors visible; provider failure cannot fabricate a reply | provider adapter, message status and UI | Missing key, timeout and invalid selection rejected |
| IMG-01 | Supplied images accessible only to authorized cohort; learner observes before assistance | asset endpoint and image UI | Cross-cohort asset denial; independent observation required |
| IMG-02 | Uploaded educational raster images bounded, metadata stripped and privately persisted | upload/analysis/jobs | MIME/dimensions/size/path abuse and ownership check |
| IMG-03 | Neural object predictions distinguished from authored observations and interpretations | `ai/cv.py`, annotation overlay | Actual inference and matching display coordinates; no accessibility/diagnosis conclusion |
| ATT-01 | Attempts persist across page/application restart; draft recoverable | Attempt, Message, Draft/Submission | Reload resumes draft/transcript, restart preserves records |
| ATT-02 | Submission immutable and idempotent; retries do not duplicate feedback | submit, bridge, feedback constraints | Same key retry succeeds consistently; changed payload conflict |
| EVI-01 | Retrieval returns exact permitted approved passages within case scope | evidence service and MCP tool | Empty unapproved corpus explicit; approved passage ID/text retrievable |
| FB-01 | Scores are provisional and based on learner's exact text or abstention | baseline rubric and report | Offset slice equals original submission; patient speech not student evidence |
| FB-02 | Educator amendment retains original feedback with actor/time/reason | FeedbackReview and educator UI | Amendment visible; original output preserved; wrong cohort denied |
| REC-01 | Next-practice recommendation transparent and eligible; synthetic model not promoted | rule baseline; `ml/train.py` | Only authorized available cases; mode/reason present |
| REC-02 | Supervised target uses historical data available before next attempt | grouped validator/training | Learner/case overlap or future-feature provenance rejected |
| AGT-01 | Workflow bounded by allowed tools/calls/deadline; trusted scope not supplied by model | `ai/agent.py` | Budget exhaustion, invalid planner choice and failure close safely |
| MCP-01 | Real MCP initialization, tool discovery and scoped actual calls | `services/mcp` + bridge | SDK transcript, forged/expired scope, cross-cohort, idempotent write tests |
| JOB-01 | Durable job status, ownership, deduplication and restart/retry behavior | API jobs; Celery worker | Duplicate analysis input, wrong-owner polling, interrupted job recovery |
| REP-01 | Learner export states case/model/rubric versions, citations, review status/time | report endpoint | Own Markdown report downloadable; another learner denied |
| PRIV-01 | Consent optional for learning; research export restricted/disabled by default | Consent/ResearchExport, config | Withdrawal respected in future export; no direct-identifier export |
| PRIV-02 | Eligible own personal data deletion revokes access and removes owned attempts/artifacts | privacy endpoint | Session/attempt/job/report removed; audit minimized; backup retention documented |
| OPS-01 | Production has non-root app images, HTTPS origin, persistent DB/assets and private internal ports | `infra/` | Build/migrate/health/full local stack and staging smoke |
| OPS-02 | Backups/restore/rollback demonstrable with version records | infrastructure scripts + runbook | Disposable restored database/assets usable; matching source/model revisions |

## Non-functional requirements

| ID | Proposed acceptance / constraint | Evidence needed |
|---|---|---|
| NFR-01 | Ordinary browser; no mandatory camera/special hardware | Browser journey and permissions controls |
| NFR-02 | Accessible labels, keyboard operation, responsive layouts, visible error/wait states | UI review and Playwright checks; complete accessibility audit pending |
| NFR-03 | Bounded request/file/provider/tool resources and no private dialogue in logs | Focused abuse tests + redacted log inspection |
| NFR-04 | CPU model memory/latency and low-bandwidth usability measured before capacity claims | Named device, network, cold/warm measurements and bytes |
| NFR-05 | Locked Python/npm dependencies and current dated official interface verification | `uv.lock`, npm lock, build/test logs and model hashes |
| NFR-06 | Formative use only; unsupported facts/references abstain; original content provenance visible | Fidelity/grounding fixtures plus independent educational benchmark |

Capacity, latency, affordability, learning benefit and language fairness have **no certified target/result** yet. Educators must predeclare practical thresholds in the benchmark before outcomes are analyzed. See [release gates](RELEASE_PLAN.md).
